# Technical review — 2026-11-03

## Scope and evidence

Manual review of Cheaper Air's React search state, FastAPI routes, agent tool validation, provider parsing, deterministic comparison, seller handoffs and persistence. This is a focused review, not a penetration test or a full audit of every repository in the account. Findings refer to the code before this documentation commit. No runtime fixes were made during this review.

Validation on the local checkout:

- Backend: 56 tests passed, 1 PostgreSQL integration test skipped because TEST_DATABASE_URL was not set.
- Frontend production build: passed.
- npm audit: zero reported vulnerabilities in the installed dependency graph at review time. This does not assess Python dependencies or establish absence of vulnerabilities.
- Malformed seller-response reproduction: both null search_metadata and null search_parameters caused an unhandled AttributeError using an httpx mock transport. No paid provider calls were made.

## Findings

### P2 — Changing market selections leaves earlier results visible

Location: frontend/src/App.jsx, sales-market chip handler.

After a successful search, toggle a market. The handler updates criteria directly without clearing result, unlike the shared change handler. The form then shows the new selection while prices, counters, map and seller links still belong to the earlier search. Route all criteria changes through a shared invalidation path and test this transition.

### P2 — Late responses overwrite newer form choices

Location: frontend/src/App.jsx, search, askAgent and applyResult.

While a search is pending, airport/date/mode inputs remain editable. Changing them clears the current result, but the pending response subsequently calls applyResult and restores its older criteria. An old REAL request can therefore replace a newly selected MOCK form, or vice versa. Associate requests with a criteria revision and discard outdated responses, or disable all criteria edits for the duration. Add a browser test with a delayed mocked response.

### P2 — Malformed seller metadata escapes the provider error contract

Location: backend/src/cheaper_air/providers/serpapi.py, booking_stage.

A JSON object with search_metadata=null or successful metadata plus search_parameters=null raises AttributeError on .get. The exception is not translated into a ProviderError, so the endpoint returns an internal error instead of the documented structured provider failure. Validate these nested objects before accessing them and add regression tests for null and non-object values.

### P3 — Health metadata always reports MOCK

Location: backend/src/cheaper_air/main.py, live and ready health routes and application description.

Health responses hard-code data_mode=MOCK even when REAL is configured and functioning. Health should describe service health and available capabilities without asserting the mode of an individual search. The capabilities endpoint already distinguishes configured providers.

## Positive observations and boundaries

- REAL results are separate from verified MOCK comparisons and do not claim confirmed savings when fare terms are unknown.
- Seller handoffs validate selected itinerary segments and do not treat missing seller prices as confirmed prices.
- Money calculations use Decimal; LLM output is validated before tools execute.
- The application is documented as local and unauthenticated. This review does not approve public hosting.
- Browser checks are documented manually; this review did not execute a browser regression suite.
